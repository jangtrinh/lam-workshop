3.1 DESIGN.MD — Nguồn Sự Thật Duy Nhất

SESSION 3.1
TRANSCRIPT

Session 3.1. DESIGN.MD. Một file Markdown bằng toàn bộ design system.

NGHE — ATTENTION HOOK
TRANSCRIPT

Thử nghiệm này: yêu cầu năm AI tool khác nhau tạo một trang landing "clean, minimal, warm." Bạn sẽ nhận được năm thiết kế hoàn toàn khác nhau. Màu khác, spacing khác, typography khác. Vì "clean minimal warm" không có nghĩa gì cụ thể. DESIGN.MD thay thế cảm giác bằng giá trị thật. Một designer đã thử: chuyển từ mô tả bằng lời sang DESIGN.MD, và tỉ lệ nhất quán của AI output tăng từ 30% lên 95%, trên mọi tool, mọi session.

ATTENTION HOOK — THE "CLEAN MINIMAL WARM" ROULETTE

Tell 5 different AI tools "create a clean, minimal, warm landing page." You get 5 completely different designs — different colors, different spacing, different typography. The words "clean minimal warm" mean nothing without specifics.

DESIGN.MD replaces vibes with values. One designer switched from verbal descriptions to DESIGN.MD: AI-generated UI consistency went from 30% match to 95% match — across every tool, every session.

Core Concept: 9-Section DESIGN.MD

NGHE — KHÁI NIỆM CHÍNH
TRANSCRIPT

DESIGN.MD có chín section. Section một đến sáu đến thẳng từ output của Level 2: tokens từ session 2.1, component specs từ 2.2, và audit rules từ 2.3. Section bảy là Do's và Don'ts từ kết quả audit. Section tám là Responsive Behavior. Section chín là điều mới: Agent Prompt Guide, những prompt copy-paste sẵn cho các AI tool. DESIGN.MD không phải viết từ đầu mà compile từ công việc bạn đã làm.

DESIGN.MD không cần viết từ đầu — đây là bản compilation của toàn bộ Level 2 vào một file portable, version-controlled:

CROSS-DOMAIN — ARCHITECTURE (DESIGN BRIEF)

Architects don't hand contractors a mood board saying "make it feel modern." They write a Design Brief: exact materials, dimensions, tolerances, constraints. The contractor reads and builds to spec. DESIGN.MD is your Design Brief. The AI agent is the contractor.

Shortcut: Figma MCP → DESIGN.MD Tự Động

TẠI SAO DÙNG FIGMA MCP

Manual compile từ Level 2 mất 30-60 phút. Figma MCP cho phép AI agent đọc trực tiếp design system từ Figma file — extract tokens, components, styles — rồi auto-generate DESIGN.MD trong 2 phút. Bạn review và sửa thay vì viết từ đầu.

Figma MCP là gì?

Model Context Protocol (MCP) là cầu nối giữa AI agent và external tools. Figma cung cấp official MCP server tại mcp.figma.com — AI agent đọc được file Figma, extract design tokens, đọc component specs, và thậm chí viết ngược lại Figma canvas.

Khả năngChi tiết
Đọc Design TokensColors, typography, spacing, effects — extract từ Figma styles
Đọc ComponentsVariants, properties, instances — từ component library
Đọc LayoutAuto layout, constraints, responsive rules
Đọc AnnotationsDev Mode annotations, comments, specs
Viết CanvasTạo shapes, text, frames ngược lại Figma (beta)

Prompt Mẫu: Auto-Generate DESIGN.MD từ Figma

Read the Figma file at [paste Figma URL here].

Extract the complete design system and generate a DESIGN.MD
file with these 9 sections:

1. Visual Theme & Atmosphere — describe the overall mood
2. Color Palette & Roles — all colors with hex + semantic roles
3. Typography Rules — all font families, sizes, weights, hierarchy
4. Component Stylings — buttons, cards, inputs with all states
5. Layout Principles — spacing scale, containers, grid system
6. Depth & Elevation — shadows, layering, surface hierarchy
7. Do's and Don'ts — 10+ rules based on the design patterns
8. Responsive Behavior — breakpoints, scaling, collapse rules
9. Agent Prompt Guide — 3 copy-paste prompts for generating
   pages that match this design system

Use concrete values (hex codes, px values, font names).
No abstract descriptions like "primary color" — use actual values.

KEY INSIGHT — DÙNG CẢ HAI

Figma MCP cho bạn bản draft nhanh trong 2 phút. Nhưng AI có thể miss context (tại sao chọn màu này? khi nào dùng variant này?). Dùng Level 2 knowledge để review và bổ sung — đặc biệt Section 7 (Do's/Don'ts) và Section 9 (Agent Prompt Guide) cần human judgment.

LIMITATIONS

Figma REST API (full token extraction) yêu cầu Figma Enterprise. Free accounts giới hạn 6 MCP tool calls/tháng. Workaround: Dùng Figma MCP để extract một lần, save DESIGN.MD vào git, rồi làm việc từ file — không cần gọi MCP lại.

BEST PRACTICE — VERSION CONTROL YOUR DESIGN.MD
DO THIS

Version-control DESIGN.MD trong git. Khi design thay đổi, commit với message có ý nghĩa: "Update primary color from #1a1a2e to #0f0f23 — tested better contrast." Điều này đóng Gap 5 (version control) trong Grand Masterplan của bạn.

AVOID THIS

Đừng viết DESIGN.MD từ đầu. Compile từ Level 2 outputs: tokens (2.1) + component specs (2.2) + audit rules (2.3). File gần như tự viết chính nó nếu bạn đã làm đúng Level 2.

NGHE — BÀI TẬP
TRANSCRIPT

Tổng hợp toàn bộ output Level 2 thành một DESIGN.MD hoàn chỉnh. Chín section, không section nào bỏ trống. Sau đó commit lên git. Test bằng cách paste vào Gemini và hỏi nó mô tả một trang — output phải khớp với design intent của bạn. Đây là khoảnh khắc bạn biết Level 2 của mình đã vững chưa.

SESSION 3.2
TRANSCRIPT

Session 3.2. Antigravity Prototyping. Từ không có gì đến prototype chạy thật trong mười lăm phút.

NGHE — ATTENTION HOOK
TRANSCRIPT

Một designer mất ba ngày trong Figma. Mockup đẹp. Chuyển cho developer. Câu hỏi đầu tiên: "Hover state trông thế nào?" Câu hai: "Loading state ở đâu?" Câu ba: "Mobile thì layout ra sao?" Không có gì được document. Với Antigravity cộng DESIGN.MD, prototype chính là documentation. Hover state hoạt động. Loading state nhìn thấy được. Responsive mặc định. Prototype trả lời câu hỏi của developer trước khi họ hỏi.

ATTENTION HOOK — THE FIGMA HANDOFF GAP

A designer spent 3 days in Figma. Beautiful mockup. Handed to developers. First question: "What happens on hover?" Second: "What's the loading state?" Third: "How does this work on mobile?" None documented.

With Antigravity + DESIGN.MD, the prototype IS the documentation — hover states work, loading states are visible, responsive by default. The prototype answers developer questions before they ask.

Core Concept: The 6-Step Vibecoding Flow

NGHE — KHÁI NIỆM CHÍNH
TRANSCRIPT

Sáu bước vibecoding. Bước một: load DESIGN.MD vào Antigravity context. Bước hai: describe bằng tiếng Việt, ví dụ "tao trang pricing với ba tier, dark header, testimonials." Bước ba: Antigravity tạo HTML cộng Tailwind cộng JS. Bước bốn: review theo Do's và Don'ts trong DESIGN.MD. Bước năm: iterate bằng ngôn ngữ tự nhiên. Bước sáu: validate lại bằng audit loop từ session 2.3. Bước quan trọng nhất là bước một. Nếu DESIGN.MD không load, bước hai trở đi sẽ drift.

Step 1: LOAD
  → Paste DESIGN.MD vào Antigravity context
  → Verify: AI acknowledges your design system

Step 2: DESCRIBE (viết tiếng Việt)
  → "Tao trang pricing với 3 tiers, dark header, testimonials"
  → "Thêm dashboard với sidebar, charts, notification bell"
  → "Xây settings page với toggle switches và form inputs"

Step 3: GENERATE
  → Antigravity sinh HTML + Tailwind CSS + Vanilla JS
  → Output là real code, chạy được ngay trong browser

Step 4: REVIEW
  → Mở browser, test click/hover/mobile
  → Check 5 random elements against DESIGN.MD Do's & Don'ts

Step 5: ITERATE (tự nhiên)
  → "Đổi hero sang dark mode"
  → "Thêm loading animation cho button"
  → "Tăng font heading lên một bậc"

Step 6: VALIDATE
  → Chạy lại audit loop từ Session 2.3
  → Target: 0 deviations từ DESIGN.MD tokens

SESSION 3.3
TRANSCRIPT

Session 3.3. Multi-Page System với Stitch. Ba trang liên kết với navigation, state, và data nhất quán.

NGHE — ATTENTION HOOK
TRANSCRIPT

Mọi AI demo đều cho thấy tạo một trang. Ấn tượng. Nhưng product không phải một trang. Ngay khi bạn cần trang thứ hai, consistency vỡ: header height khác, sidebar width khác, card style khác. Multi-page consistency khó hơn single-page mười lần. Một designer dùng Stitch cộng DESIGN.MD ship prototype năm trang trong hai giờ và pass QA ngay lần review đầu tiên vì mọi trang đều đọc cùng một design system.

ATTENTION HOOK — THE SINGLE-PAGE TRAP

Every AI demo shows generating ONE page. Impressive. But products aren't one page. The moment you need page 2, consistency breaks: different header height, different sidebar width, different card style.

Multi-page consistency is 10x harder than single-page generation. A designer using Stitch + DESIGN.MD shipped a 5-page prototype in 2 hours that passed QA on first review — because every page read the same design system.

Core Concept: Page System Architecture

NGHE — KHÁI NIỆM CHÍNH
TRANSCRIPT

Kiến trúc rất đơn giản. DESIGN.MD làm gốc. Từ đó generate shared.css trước tiên. Rồi mỗi trang import shared.css. Shared CSS là layer enforcer: tất cả trang kế thừa cùng tokens. Không phải bằng cách lặp lại prompt, mà bằng kiến trúc. Generate shared.css trước, rồi trang một, validate, rồi trang hai và ba. Không generate song song. Sequential.

DESIGN.MD (shared source of truth)
    |
    +-- shared.css (generated from DESIGN.MD tokens)
    |       → All color variables
    |       → All typography rules
    |       → All spacing scale
    |       → All component classes
    |
    +-- index.html    (Landing: hero, features, CTA)
    |   └── <link rel="stylesheet" href="shared.css">
    |
    +-- dashboard.html  (Data: charts, tables, stats)
    |   └── <link rel="stylesheet" href="shared.css">
    |
    +-- settings.html   (Forms: toggles, inputs, profile)
        └── <link rel="stylesheet" href="shared.css">

SHARED COMPONENTS (đặt trong shared.css hoặc components/)
    +-- Navigation (identical on all pages)
    +-- Footer (identical on all pages)
    +-- Notification patterns (consistent behavior)
KEY INSIGHT — ARCHITECTURE BEFORE CONTENT

Generate shared.css từ DESIGN.MD TRƯỚC TIÊN. Rồi mọi trang import nó. Đây là architectural decision — shared stylesheet enforce consistency về mặt structural, không phải bằng cách lặp prompt. Thay đổi một token trong shared.css = tất cả trang cập nhật ngay.

NGHE — CROSS-DOMAIN INSIGHT
TRANSCRIPT

Nhà xuất bản sách dùng style guide: một document quản lý mọi trang — margins, fonts, heading styles, caption rules. Mỗi author chương đều theo cùng một guide. shared.css của bạn là style guide đó. Mỗi AI tạo ra một trang đều follow nó tự động.

CROSS-DOMAIN — PUBLISHING (STYLE GUIDES)

TRANSCRIPT

Build prototype ba trang với shared navigation. Generate shared.css từ DESIGN.MD trước. Sau đó ba trang, mỗi trang đều import shared.css. Verify navigation click được giữa tất cả trang. Cuối cùng chạy full audit cross-page: zero inconsistencies.

EXERCISE

Build a 3-Page Prototype

Tạo 3 trang liên kết với shared navigation theo đúng thứ tự:

  1. Generate shared.css — từ DESIGN.MD tokens (Stitch hoặc Antigravity)
  2. Build navigation shell — header + nav links + footer (import shared.css)
  3. Trang 1: Landing — hero, features, CTA. Audit. Fix.
  4. Trang 2: Dashboard — sidebar, data widgets, charts. So sánh với Trang 1.
  5. Trang 3: Settings — forms, toggles, profile section
  6. Cross-page audit — header/footer identical? Card styles consistent? 0 deviations?
SUCCESS CRITERIA
APPLY CHALLENGE

Thêm trang thứ 4 vào prototype của bạn — một trang hoàn toàn mới, loại khác (ví dụ: trang onboarding, hoặc trang profile). Generate bằng Stitch + shared.css đã có. Verify: trang mới nhất quán 100% với 3 trang trước mà không cần thêm prompt context.

LEVEL 3 SELF-CHECK QUIZ
Q1: Tại sao DESIGN.MD hiệu quả hơn mô tả bằng lời cho AI consistency?
  • A) Prompt dài hơn thì tốt hơn
  • B) Giá trị cụ thể (hex, px, weights) loại bỏ interpretation variance
  • C) AI thích đọc Markdown hơn
  • D) DESIGN.MD ngắn hơn nên token hiệu quả hơn
B — "Clean minimal warm" có thể có nghĩa là 1000 thiết kế khác nhau. Hex #0f0f23, font-size 56px, spacing 8pt grid chỉ có một nghĩa duy nhất. Giá trị cụ thể = zero interpretation variance.
Q2: Antigravity output drift khỏi design system. Nên fix cái gì trước?
  • A) Task prompt — mô tả chi tiết hơn
  • B) DESIGN.MD — quá mơ hồ hoặc thiếu constraints
  • C) Chuyển sang AI model khác
  • D) Generate lại từ đầu
B — Nếu output drift, root cause là DESIGN.MD thiếu hoặc mơ hồ. Fix gốc rễ: thêm constraints, cụ thể hóa values. Prompt-tweaking chỉ là patch tạm thời.
Q3: Tại sao generate shared.css TRƯỚC khi generate từng trang?
  • A) Nhanh hơn
  • B) Structural enforcement — tất cả trang kế thừa cùng tokens
  • C) Dễ debug hơn
  • D) Stitch yêu cầu shared.css trước
B — shared.css là layer enforce tất cả trang theo cùng một design system về mặt structural. Không cần repeat prompt context cho mỗi trang — architecture làm việc thay bạn.
Q4: Section 9 của DESIGN.MD là gì và tại sao nó tồn tại?
  • A) Changelog — lịch sử thay đổi design system
  • B) Agent Prompt Guide — pre-written prompts cho AI tools để interpret đúng
  • C) Credits — ai đã đóng góp vào design system
  • D) Appendix — phần bổ sung không bắt buộc
B — Section 9 là cầu nối giữa design specification và AI execution. Pre-written prompts cho phép bất kỳ tool nào (Antigravity, Stitch, Gemini) follow đúng design system mà không cần bạn giải thích lại mỗi lần.
Q5: Prototype 3 trang có card shadows không nhất quán. Nguyên nhân khả năng cao nhất?
  • A) Bug trong Antigravity/Stitch
  • B) Shadow tokens bị thiếu trong shared.css hoặc DESIGN.MD Section 6
  • C) Browser rendering khác nhau
  • D) Cần regenerate tất cả trang
B — Inconsistent shadows = shadow tokens chưa được define trong DESIGN.MD Section 6 (Depth & Elevation) hoặc chưa được export vào shared.css. Fix: define shadow-sm, shadow-md, shadow-lg trong DESIGN.MD và regenerate shared.css.
